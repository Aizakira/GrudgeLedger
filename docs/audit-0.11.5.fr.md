# Vérification des tickets — 0.11.5

Vérification du 18 novembre 2026 sur la version intégrée, avec les correctifs de partage de fiches et d’alertes de primes. Les contrôles ci-dessous utilisent le code réel dans un client simulé Lua 5.1. Ils ne constituent pas un essai dans Forever avec deux joueurs.

| Ticket | Diagnostic et contrôle reproductible | Conclusion |
| --- | --- | --- |
| [#18](https://github.com/Aizakira/GrudgeLedger/issues/18) — participation à une mort en combat mixte | `Tracker.lua` relève les dégâts et le récapitulatif de mort, puis `Core.lua` déduplique les événements. `tracker_test.lua` couvre le dernier coup d’une créature après les dégâts d’un joueur, le joueur seul, deux morts après résurrection, les signaux répétés et l’absence de crédit pour le simple témoin. | Correction déjà présente, scénarios revérifiés. |
| [#19](https://github.com/Aizakira/GrudgeLedger/issues/19) — portrait générique hors de portée | Le cache natif était conservé, mais le modèle animé approximatif pouvait le recouvrir. `UI.lua` donne maintenant priorité au portrait natif mémorisé ou archivé lorsque le personnage n’est plus visible. `identity_ui_test.lua` contrôle la liste, la fiche, la sortie de portée, les événements de mort/libération et une réponse tardive du modèle. | Défaut résiduel corrigé dans cette version. |
| [#20](https://github.com/Aizakira/GrudgeLedger/issues/20) — alerte après résurrection | `Display.lua` réarme les alertes seulement après une vraie résurrection. `display_test.lua` fait disparaître puis revenir la barre de nom, sans ciblage, vérifie une nouvelle alerte sonore et l’absence de répétition sur les rafraîchissements suivants. | Correction déjà présente, scénario revérifié. |
| [#21](https://github.com/Aizakira/GrudgeLedger/issues/21) — honneur reçu et gain adverse | L’honneur nommé, partagé, anonyme et explicitement nul est traité séparément des coups fatals. `tracker_test.lua` vérifie notamment les messages français ; `honor_journal_test.lua` vérifie les vues. Le code affiche « Honneur adverse inconnu ». L’essai comparant les messages réellement reçus par deux joueurs, demandé dans le ticket, n’a pas été effectué. | Fonction locale déjà présente ; ticket conservé ouvert pour la vérification du gain adverse dans Forever. |
| [#22](https://github.com/Aizakira/GrudgeLedger/issues/22) — suppression des résultats « probables » | Seule la migration conserve les noms des anciens champs. Les vues utilisent les compteurs communs. `reputation_balance_test.lua` reproduit une mort et une agression anciennes : 1 mort et −11 après deux initialisations, aucun doublon au second signal, puis 2 morts après une nouvelle rencontre. Les tests du journal, des classements et des corrections contrôlent les autres vues. | Correction déjà présente, scénario de migration renforcé. |

## Limites à vérifier en jeu

Le client doit fournir une observation exploitable : l’addon ne peut pas identifier un attaquant entièrement absent des événements accessibles. Pour les portraits, les images natives en mémoire sont limitées à la session et au cache existant ; la conservation après redémarrage dépend de l’archive privée du compagnon. Sans portrait natif, l’aperçu reconstitué reste explicitement approximatif.

Après installation, redémarrer Forever pour charger le nouveau module de partage. Refaire les scénarios des tickets en jeu ; pour #21, relever les messages des deux participants lors de la même rencontre avant de conclure sur la disponibilité du gain adverse. Aucune donnée personnelle de partie n’est incluse dans les tests ou le ZIP.
